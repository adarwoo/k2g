# Privacy

The short version: k2g makes exactly one network request, it is switchable off, and it sends nothing about you or your work.

## No telemetry

There is no analytics, no usage tracking, no crash reporting, no licence check, no "anonymous statistics". None of it is present in the code, and none is planned. Your boards, profiles, tooling and generated G-code never leave your machine.

You do not have to take that on trust. The source is public, and the dependency list in `Cargo.toml` contains one HTTP client, used in one module (`src/runtime/update.rs`) for the one purpose described below.

## The one network request

When **Settings → Updates → Check for updates automatically** is on, k2g asks GitHub once every 24 hours whether a newer release exists:

```
GET https://api.github.com/repos/adarwoo/k2g/releases/latest
```

**What GitHub can see.** Any HTTPS request discloses your IP address to the server, and k2g sends a `User-Agent` naming the version you run (`k2g/0.9.0 (+https://github.com/adarwoo/k2g)`). GitHub therefore learns, roughly, that a machine at your address is running that version. This is not anonymous, and describing it as such would be untrue. It is GitHub's normal request logging and is governed by their privacy statement, not by k2g.

**What is *not* sent.** No account name, no machine name, no file paths, no board data, no profile data, no identifier of any kind generated by k2g. The request has no body and carries no cookie. k2g does not have or create a user ID.

**Turning it off.** Settings → Updates → uncheck *Check for updates automatically*. k2g then makes no network requests at all, and you take updates from the [releases page](https://github.com/adarwoo/k2g/releases) when you choose to.

Installing an update is always a separate, explicit click. Nothing downloads on its own, and every download is signature-checked before it is run.

## What is stored, and where

Everything k2g keeps is in one directory on your machine:

| Platform | Location |
|---|---|
| Windows | `%APPDATA%\k2g` |
| macOS | `~/Library/Application Support/k2g` |
| Linux | `$XDG_CONFIG_HOME/k2g`, else `~/.config/k2g` |

```
configs/     settings, machine/fixture/machining/toolset profiles, stock, the job
catalogs/    tool catalogs — seeded from the bundled defaults, then yours to edit
logs/        the security record described below
```

Nothing is stored anywhere else, and nothing is stored online. The one thing k2g writes outside this directory is the KiCad plugin registration, if you ask for it — see below.

## The security record

With **Settings → Security recording** on (the default), k2g appends a line to `logs/security.jsonl` when something security-relevant happens: update checks and installs, changes to either of these switches, KiCad plugin registration and API-setting edits, configuration files rejected as invalid, G-code written to disk, and resets or deletions.

This exists because a tool that edits another application's configuration and can install software should be able to tell you what it did and when. It is required of products in scope of the EU Cyber Resilience Act (Annex I (2)(l)), which asks for exactly this together with a user opt-out.

- **It stays local.** Nothing in it is transmitted anywhere, by this feature or any other.
- **It holds no personal data.** Paths are rewritten before they are stored: your home and temp directories become `~`, so `C:\Users\jane\Documents\panel.gcode` is recorded as `~\Documents\panel.gcode`. On Windows especially, an un-redacted path usually contains a real name.
- **It records file names, not file contents.** The G-code itself, your board and your profiles never appear in it.
- **It is bounded.** Two files of 2 MB at most; older entries are discarded.
- **You can read and export it.** Logs screen → *Security* tab → *Export…*
- **You can switch it off**, in Settings. Switching it off also offers to delete what was kept. The last thing written before it stops is the fact that it stopped, so the gap in the record is explainable rather than mysterious.

The *Diagnostics* tab on the same screen is a different thing: an in-memory tail of the current run, never written to disk, gone when k2g closes.

## What k2g writes outside its own directory

Two things, both only when you ask for them on the Settings screen, and both undoable there:

1. **A KiCad plugin registration** — a small directory under `Documents/KiCad/<version>/plugins/k2g` holding a manifest, an icon and a launcher. *Unregister* removes it.
2. **KiCad's `api.enable_server` setting** — one key in KiCad's own `kicad_common.json`. A `.k2g-backup` copy of the file is written first, and no other setting is touched.

Both are recorded in the security log, including the backup's location.

## Removing everything

- **Settings → Data and reset → Reset settings** clears your settings, profiles, stock and job, and re-creates the shipped defaults. Catalogs and the security log are kept.
- **Settings → Data and reset → Delete all data** removes the entire directory above — settings, catalogs, logs, everything — and closes k2g.
- Unregister the KiCad plugin separately from the KiCad integration card, if you registered it.
- Then uninstall k2g through Windows' Apps & features, or delete the portable folder.

**On "secure" deletion.** These operations delete files; they do not overwrite the underlying storage. On an SSD, overwriting a file's bytes does not reliably destroy the physical copy anyway — wear levelling relocates writes, so the old blocks survive under a different mapping. If you need guaranteed erasure, that is a job for full-disk encryption or the drive's own secure-erase, not for an application. What deletion here does guarantee is that k2g itself retains nothing.
